# 个人交易伙伴：从收集到成果，再到行动

> 历史设计：当前 0.4.0 使用问题专题、个人知识、方法与实践流程，见 [实现与使用说明](product-growth-implementation.md)。

版本 0.3.0 · 2026-10-04

本文描述已发布的 0.3.0。下一阶段根据用户反馈重新设计的方向见 [个人交易成长伙伴：总体设计提案](product-growth-blueprint.md)，该提案尚未实现或发布。

## 初衷与目标

这是一个个人交易工作台，帮助自己把零散信息整理成可回查、可理解、可实践的积累。日常说得自然；需要时找得到；阅读时分得清结论和依据；行动时有合适的方法与工具。

目标不是让资料数量不断增长，也不是展示很多模块。核心闭环是：**对话收集 → 整理成果 → 阅读与检验 → 个人方法与纪律 → 在下一次实践中使用 → 再复盘。**

本轮保留现有对话和多种输入。重点重做知识库与交易体系。手机网页和电脑网页使用同一份前端与云端资料。按用户最新要求，小程序备案尚未完成，暂不调试、导入或发布小程序。

## 三个入口的分工

| 入口 | 核心问题 | 最重要的内容 | 主要动作 |
| --- | --- | --- | --- |
| 对话 | 我现在想记录、研究或弄清什么？ | 当前输入、附件、回复和真实引用 | 收集、追问、研究、整理成果 |
| 知识库 | 已经积累了哪些值得查阅的成果？ | 成果正文与摘要，其次是边界、验证和来源 | 阅读、检索、归档、主题分类、收藏 |
| 交易体系 | 我按什么原则行动，怎样完成一件事？ | 原则、正式纪律、工作技能和具体工具 | 选工作方法、检查纪律、打开工具 |

知识库以阅读为中心；体系以行动为中心。两者通过真实资料引用连接，不再重复展示同一套四层记录列表。

## 知识库：成果优先，分层管理

### 第一层：资料所处的位置

| 层级 | 内容 | 默认组织方式 |
| --- | --- | --- |
| 整理成果 | 研究分析、案例复盘、体系回顾、已形成个人理解的学习总结 | 分析、复盘、演变和有 understanding 的学习条目默认进入；其他可整理内容可手动归档 |
| 待打磨 | 零散笔记、候选认识、研究线索、规则提案 | 保留想法，逐步整理，避免短笔记混入成果首页 |
| 资料档案 | 原话、外部来源、行情、持仓、成交、计划、个人背景、生效纪律及处理留痕 | 保留原始依据与业务事实；不直接移动为成果，另行整理输出 |
| 经典书架 | 已有公开经典条目 | 原意、理解、边界、来源分开阅读；独立于个人认同 |

默认归档依据内容类型，表示“这是整理后的输出”，不表示“已证明正确”。用户可以在详情里调整非档案内容的层级。原始档案可以分类、收藏，正文与历史保持原样。

### 第二层：阅读主题

提供交易认知、风险与仓位、交易执行、复盘方法、市场研究、心态与习惯，以及未分类。主题由用户整理，不按关键词擅自替用户贴标签。搜索、类型、收藏与待回查可组合筛选；收藏在同一筛选内优先显示；每页 12 份。

这版先采用固定主题，保持简单。多层自定义文件夹、批量整理和自动主题提案留给后续真实使用反馈。

### 第三层：阅读深度

1. 卡片展示标题、优先摘要、类型、主题、收藏与必要状态。
2. 详情先显示成果正文与适用边界，让内容成为主体。
3. 归档管理折叠展开，选择层级、主题、收藏后明确保存。
4. 来源、个人认同、实践证据、纪律状态分别显示。
5. 关联资料显示可读标题，打开后继续追溯；版本正文折叠保留。

“成果”与“已验证”是两回事。发现反例或资料更正时，卡片会提示回查；移动到成果库也不会改变认同、证据或纪律。

### 从笔记到成果

点击“整理一份成果”准备一条对话任务，由用户补充和发送。智能体先寻找适合整理的真实记录，明确范围，再形成标题、核心结论、依据、边界与后续验证。写入实际成功后才确认保存。短笔记仍先归集，避免为每一句话生成报告。

## 交易体系：道、法、术、器各有角色

### 道：方向与原则

展示个人目标与背景，以及明确标为个人已认同的原则；待吸收认识单独展示。尚未形成的内容保持空白，可以进入对话梳理目标、时间、资金用途与风险边界。不从经典名言或模型总结直接补造“我的信念”。

### 法：纪律与规则

只以真实生效版本展示当前纪律，保留确认依据和版本。修改提案独立阅读，不能把候选心得显示成生效纪律。没有生效版本时，提供准备提案的入口，不展示通用规则冒充个人纪律。

本轮仍不提供纪律激活按钮。规则的正式确认流程和交易有效性是两个独立问题。

### 术：方法与工作技能

以已接入的工作技能作为主要内容，每项写清准备什么、得到什么、边界在哪里：

| 工作技能 | 输入 | 交付 |
| --- | --- | --- |
| 交易计划检查 | 计划、周期、持仓 | 信息缺口、失败路径、条件方案 |
| 交易经验复盘 | 原计划、成交、当时判断 | 案例复盘、候选经验、验证问题 |
| 知识学习与吸收 | 文章、语录、读书笔记 | 学习总结、原意、理解、边界与实践候选 |
| 体系与环境回顾 | 方法变化、反例、旧规则与新认识 | 竞争解释、适配边界、修改提案 |

可用状态来自引擎实际技能与工具注册；模型未配置时明确显示。按钮把任务带入对话，保留现有草稿，等待用户发送。

个人方法积累作为第二层依据，折叠展开。它与程序技能不是同一个概念：前者是个人候选或已形成的认识，后者是实际可调用的工作流程。

### 器：具体工具

| 工具 | 实际操作 | 数据边界 |
| --- | --- | --- |
| 仓位与风险计算 | 输入一笔或多笔数量、当前价格、可选退出情景和账户总资产，计算市值、占比与情景变动 | 不需要模型；本次输入不保存为持仓或成交；缺账户总资产不计算比例 |
| A 股行情查询 | 按名称或代码查公开报价，歧义时选择证券 | 展示来源、数据时间与延迟状态；不保存此次快照，不作实时性保证 |
| 持仓与交易台账 | 分开浏览历史持仓快照和成交，打开正文、来源与版本 | 个人自述，不推导为当前完整券商账户 |
| 纪律条件检查 | 按当前生效规则提供所需字段，确定性检查条件 | 空项、描述性规则及未支持条件保留待判断；没有生效纪律时不借候选规则替代 |

工具各有独立操作面板。“器”不再是贴了 qi 标签的笔记清单。旧标签仍保留在业务资料中，供角色执行与回查使用，不据此推导工具能力。

## 视觉与交互

沿用暖白与墨绿，标题使用克制的宋体，操作与正文使用系统字体。层级来自留白、字重、阅读顺序和必要状态，减少装饰性指标。资料用卡片扫读，技能明确输入与产出，工具通过表单操作。

桌面知识卡片三列，技能与工具两列；手机单列。一级导航随页面滚动保持可见；工具与阅读面板在手机采用贴底的全宽面板。抽屉内部滚动，关闭和主要操作保留可见。搜索延迟 350 毫秒，旧响应不能覆盖新条件；失败可重试，空状态提供对应下一步。

归档或对话更新后刷新资料，但保留当前工作区、主题和筛选；新归档保存时回到当前筛选第一页。工具计算成功后显示结果，修改输入清除旧结果，防止把旧计算对应到新输入。

## 最小实现与边界

继续使用 uni-app / Vue 3 / TypeScript、Python、SQLite 和原 runtime_core，不更换技术栈。本轮的问题来自信息组织与行为设计，更换框架不能替代这次重构。

归档管理保存在 runtime/library.sqlite；交易原话、正文、版本、引用和独立状态仍在原业务库。浏览不会建立空业务库，归档只写阅读偏好库。新增库纳入备份，发布继续保留独立 data 目录。

暂不增加自动交易、券商同步、常驻监控、复杂权限、知识关系图谱、多层目录或批量操作。经典库仍为既有静态资料；网页没有通用联网检索或公告抓取能力。

## 本轮验收

自动测试覆盖默认归档、分类与分页、收藏跨实例恢复、原始档案边界、归档不修改正文与独立状态、真实能力状态、空库只读、登录保护、仓位结果、行情歧义及无持久写入、纪律缺项与版本、备份恢复所需的归档数据。

网页验收使用临时合成资料，未写入个人交易记忆。实际打开归档操作、四件工具及电脑/手机尺寸；公开行情查询取得带时间的真实来源报价。模型任务按钮验证草稿流转，本轮不以程序验收验证交易观点或模型分析效果。小程序按用户要求暂停验收。
