# 产品与功能检查 · 2026-10-03

## 判断

对个人交易伙伴而言，对话、知识库、交易体系三个入口分工合理：对话承接记录和研究，知识库查证和回看，体系区分方向、规则、方法与工具。应先把这条闭环做稳，暂不增加行情大屏、复杂仪表盘或更多一级菜单。

原有页面具备克制的配色和留白，但存在功能反馈、重复信息及跨端工程混用问题，不能仅根据首页截图就判定产品成熟。本轮在同一前端源码中修复，Python、SQLite 和用户引擎保持原结构。

## 本轮修复

| 环节 | 原问题 | 现在的行为 |
| --- | --- | --- |
| 模型选择 | 选择器没有显示当前模型位置 | 打开时定位到当前模型；上传、录音和回复期间禁止切换 |
| 会话恢复 | 首次创建的会话未写入本机状态 | 初始会话和后续切换都保存，刷新可恢复 |
| 归集选择 | 刷新恢复默认允许 | 记住用户选择，避免误将验收或普通讨论归集 |
| 对话失败 | 文本清空后缺少找回入口 | 保留原稿与附件供手动找回；提示先确认历史，不自动重发 |
| 流式回复 | 连接关闭可能被视为结束 | 必须收到 done 事件；中断明确提示，清除空白回复块 |
| 页面跳转 | 筛选与体系层级切换后重置 | 保留页面状态；新的资料更新后重新载入 |
| 资料讨论 | 新讨论文字覆盖现有草稿 | 在现有草稿后追加讨论入口文字 |
| 文件阅读 | 浏览器弹窗可能被拦，微信打开原文件失败无反馈 | 先提供内容预览；原文件下载保留名称，微信文档显式指定类型并提示失败 |
| 录音回放 | 缺少暂停控制和错误反馈 | 提供播放/暂停和原始转写，关闭时释放播放器 |
| 知识摘要 | 重复类型标签、Markdown 标记干扰阅读 | 普通类型只显示一次；摘要去掉格式标记，长标题与摘要限行 |
| 状态层次 | 候选与正式纪律不易快速区分 | 候选、待回查、确认分别呈现状态；正式纪律仍须真实确认 |
| 版本信息 | 默认铺开完整版本导致内容重复 | 默认收起，按需查看原文与版本 |
| 表格阅读 | 多行被水平排列 | 行纵向排列，列对齐，可横向浏览宽表 |
| 手机阅读 | 长标题、关闭按钮和底部操作可能挤压 | 关闭按钮不收缩，底部留安全区，详情作为底部阅读面板 |
| 文案 | 英文装饰与开发配置提示影响理解 | 中文说明优先，网络提示用用户能理解的语言 |
| 小程序工程 | 旧版与统一版同名，当前打开旧工程 | 已切回 frontend/dist/build/mp-weixin；旧 miniprogram 仅备用 |

## 设计取舍

采用浅暖背景、绿色主操作和有限状态色。一级导航保持三个，避免把管理选项与交易工作混在一起。卡片用于扫读，详情用于阅读，来源与历史作为证据展开。手机单列，桌面按空间安排多列。使用质感主要来自清晰层级、稳定反馈和可回查的资料，而不是增加装饰或动画。

当前详情关联仍主要以资料编号作定位，后续可改成可读标题；原稿为本机共享草稿，尚未为每个会话建立独立草稿箱；回看历史长回复时仍可能自动跟随新回复，后续可加入暂停跟随。以上保留为后续完善项，不能宣称已实现。
