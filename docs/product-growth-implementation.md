# 0.4.0：把日常积累接到个人交易体系

当前版本为 [0.5.0](product-companion-0.5.md)，新增历史整理、经典分层、实际专职协作与反馈闭环。本页保留 0.4.0 的生命周期与操作边界说明。

2026-10-04。总体方向见 [成长伙伴设计](product-growth-blueprint.md)。本页只描述这一版实际实现的内容。

产品要帮助你逐步形成适合自己生活、能讲清依据、能在实践中修订的交易体系。主线是：**持续的问题 → 自己的理解 → 有条件的方法 → 事前记录与事后复盘 → 有依据的修订**。可以停在其中任何一步，资料不必全部变成方法，方法也不必全部升级为纪律。

## 三个入口

| 入口 | 先看什么 | 怎样继续 |
| --- | --- | --- |
| 工作台 | 一个输入框、接着上次、最多三个自己留下的下一步 | 开一个专题，继续已有内容，或随手聊 |
| 知识库 | 问题专题、知识成果、实践复盘 | 先读自己的认识，再看例子、出处及版本 |
| 交易体系 | 个人手册、自己的方法、纪律修订、具体工具 | 说明怎样做，准备一次观察，决定如何修改 |

界面采用浅色阅读底、低饱和绿色、统一字阶和留白。桌面阅读与下一步并排，手机转为单栏。模型、原始资料、版本历史放在相关的次级入口。

## 一次怎样用

1. **从一个真实问题开始。** 工作台只需写一句问题，后续在专题补充当前认识、没弄清的地方和下一步。已有笔记通过“关联已有资料”带入；也可以暂时放下或归档专题。
2. **写成自己的知识。** 在专题点击“写下我的理解”，分别保留理解、边界、自己的例子和摘录。进入“一起讨论”，不用重新说明当前对象，伙伴会读到正文、所属专题、关联来源及相关案例。
3. **把理解变成可用的方法。** 从知识卡点击“看看下次怎样用”，范围、条件、步骤、失效与风险逐步补齐。未完整时可保存为构思；进入观察试用或采用前需补齐关键条件。“我在采用”仅表示个人选择。
4. **做一次观察或实践。** 从方法创建实践，自动带入关联方法、条件、失效和步骤。先写自己的判断，再锁定事前记录。后来补充实际行动、结果、判断与执行复盘、下一次改进；没有交易也可以完成。
5. **把结果接回体系。** 完成复盘后可以留下一条知识、回到方法继续完善或提出纪律修改。修订时查看完整的新旧条款、原因及提出时的依据。明确采用后才影响后续纪律检查，旧案例继续保留原来使用的版本。

## 连贯性与资料边界

- 一个专题或成果拥有独立会话。讨论中已归集的真实原话自动关联回当前对象；关闭归集时不保存业务来源或 AI 整理建议。
- AI 使用 `growth_suggest` 创建建议。建议包含目标与正文版本，只能改正文，不能替用户选择采用状态、锁定实践、判断案例意义或激活纪律。用户可采用或保留当前正文。
- 编辑和未发送的对话按对象保存本机草稿；修订草稿也可恢复。草稿暂不跨设备同步，已保存正文由云端共享。
- 引用固定到关联时的版本；来源修改后显示提醒，可以读旧版本或进入当前内容。新版不会批量改写原个人资料。
- 事前锁定保存当时的方法及生效纪律。事后修改原判断会被拒绝；正文历史仍可回查。
- 体系修订显示具体对照，支持暂缓、不采用与明确采用。完整提案指纹和用户确认会留存；旧版本提案不能覆盖后来生效的体系。
- 工具仍提供仓位风险、行情、台账和纪律条件检查。方法页面可打开计算工具；本版尚未把计算结果自动填回实践。

## 实现

继续使用 Vue 3 / uni-app、Python、SQLite 和用户提供的原运行引擎，没有更换技术栈或引入新服务。新增的专题、知识、方法、实践、手册、整理建议、来源关联及修订决定复用 `knowledge.sqlite` 的对象、关系、版本和幂等操作，不新增独立数据库。已有备份机制覆盖这些内容。

- `cloud_trading/growth.py`：生命周期、版本、来源、实践快照、建议与修订。
- `cloud_trading/growth_api.py`：用户身份下的编辑、锁定和采用接口。
- `cloud_trading/models.py`：服务端装配当前对象上下文，沿用原附件能力。
- `cloud_trading/extensions/trading_partner`：场景提示与只创建草稿的模型工具。
- `frontend/src/components/GrowthWorkspace.vue`、`GrowthDetail.vue`、`GrowthEditor.vue`：三入口、阅读、讨论和编辑。
- `SourceSnapshot.vue`、`SourcePicker.vue`、`ProposalPanel.vue`：来源回查、关联和修订审阅。

历史对象、经典与附件仍可使用原入口。上下文按阅读范围截取：前 8 份关联来源、前 12 个相关对象，字段文本设上限；不能据此声称模型已读完全部资料。引擎核心保持原文件校验。
