# 个人交易成长伙伴：总体设计提案

2026-10-04 · 总体设计与后续方向。0.4.0 已实现其中的最小完整学习与实践流程；具体范围、尚未实现的部分与验收见 [实现说明](product-growth-implementation.md)。本稿中的后续设想不代表已上线能力。0.3.0 的验收记录按原文保留。

## 1. 先重新定义要实现的结果

已有目标记录表明：用户希望在工作与家庭之外，利用业余时间提高投资交易能力，以财务自由为长期方向，并保留未来职业交易的可能；需要研究交流与复盘教练，主要关注 A 股，同时有短线和中长线需求，正在学习缠论与量价分析。

产品应帮助用户逐渐拥有一套**适合自己的生活、能说清依据、能用于决策、能经实践修订的交易体系**。资料积累、AI 回答、技能调用和工具计算都服务于这个结果。收益是长期观察结果之一，产品不能从资料量或几次盈亏推导能力成熟。

把远期目标落到五种可观察能力：

1. **有取舍**：知道为什么参与、做哪些机会、哪些钱和时间可投入、哪些事不做。
2. **能判断**：能用自己的话解释一个机会的依据、未知和失败条件。
3. **可执行**：行动前有计划，过程中知道何时继续、调整或退出。
4. **会复盘**：区分判断问题、方法问题、执行偏差和结果波动。
5. **能积累**：下一次能够找回并使用旧经验；改变方法时说得清理由。

阶段性最小成果：**完成一套方法从学习、定义、观察练习、复盘到版本修订的真实过程。**不要求先填满整套体系，观察和明确放弃也是实践。

时间投入、资金用途和可接受风险尚未明确。它们是日后个性化设计需要逐步补齐的约束，本稿不替用户设定。

## 2. 上一版为什么仍不够好

| 现状 | 实际缺口 | 本次改变 |
| --- | --- | --- |
| 对话不断追加回答 | 下一次继续时要重新交代，成果容易埋在聊天里 | 围绕同一个问题持续工作，保留上下文与下一步 |
| 按记录类型和状态分库 | “分析”“复盘”不天然等于有用、理解过的成果 | 用明确问题组织知识，成果需能读、能解释、能追溯 |
| 主题只是固定分类标签 | 同一主题下的内容没有共同回答一个问题 | 专题有当前认识、分歧、缺口和正在推进的事项 |
| 缺少学习后的动作 | 收藏、读完、认同之后就停止 | 提供解释、比较、举例、观察练习及情境回想 |
| 术主要展示四个软件技能 | 看不到用户自己的交易方法 | 术以个人方法为主体；技能成为背后的协助能力 |
| 法可以展示提案，却缺少网页确认闭环 | 用户不能顺畅决定哪些内容正式生效 | 提供具体差异、依据和一次明确确认，保留版本 |
| 器有独立工具，却与具体任务脱节 | 在工具和对话之间重复输入 | 从计划、方法或案例中打开工具，带入已有数据及其时间 |
| 很多操作最终只是塞入提示词 | 用户仍承担“怎样问、怎样整理、保存到哪”的工作 | 一次操作有明确输入、对象、产出和保存回执 |

修正上一版的核心判断：**软件的工作技能，不等于用户的交易方法。**

## 3. 用两个循环连接日常行为与长期体系

### 学习循环

提出问题 → 收集有关资料 → 说清自己的理解 → 比较不同解释 → 形成可查阅的知识成果 → 在需要时回想和使用。

### 实践循环

选择适用方法 → 写出事前判断和计划 → 观察或执行 → 补充实际发生的情况 → 分开评价判断、执行与结果 → 更新认识或提出体系修改。

两个循环通过“知识、方法和案例”连接。新知识可以改善计划；一次复盘可以提出新的学习问题。体系回顾查看这些变化是否足以修改原有做法。

不会要求每份材料走完同一流水线：

- 一篇背景资料可以长期只作为查阅资料。
- 一条学习认识可以保留分歧，不必变成规则。
- 一个纯粹的生活取舍由用户确认即可，不需要用交易盈亏证明。
- 一套市场方法需要明确适用条件和实践证据；个人认同不会使它自动有效。
- 规则可以暂停或撤回，历史实践仍按当时版本理解。

## 4. 最重要的组织单位：一个持续推进的问题

示例：“我怎样判断超跌后的机会是否值得进一步观察？”

它应成为一个可继续打开的专题，而非若干聊天记录。专题中始终可以看到：

1. **我目前的认识**：一段简洁、可编辑、有来源的阶段性结论。
2. **仍未弄清的地方**：术语不清、证据不足、观点冲突。
3. **相关知识与方法**：已经整理好的成果，以及正在形成的方法。
4. **实践记录**：支持、反例、没有交易的观察和判断失误。
5. **下一步**：一个最值得继续处理的问题；可以暂缓。

“超跌反弹”可以是专题，“底部成立怎样定义”是其中的问题，“先写出可观察条件”是一条候选做法，具体观察是案例。这些关系不能靠相同标签代替。

日常学习可以包含交易以外的知识；它们沿用相同的收集、理解和专题组织方式。只有确实相关、且用户选择应用的认识才进入交易方法与体系。开发讨论继续不进入交易记忆。

初期使用“领域 → 专题 → 成果”三层浏览。领域可从交易认知、风险管理、交易方法、研究与复盘开始；专题可由用户更名、合并或跨领域引用。一个成果只有一个正文，多处引用不复制。

## 5. 知识库应该像自己的知识书

默认打开可以阅读的成果和正在关注的专题。资料的处理状态收进筛选，原始资料进入来源区；“经典”是来源属性与阅读集合，不再与个人成果争夺同一层级。

### 成果的四种形态

| 形态 | 回答什么 | 主要内容 |
| --- | --- | --- |
| 知识卡 | 一件事我现在怎样理解？ | 一句话认识、解释、适用边界、自己的例子、原始来源 |
| 专题笔记 | 关于这个问题，我目前学到了什么？ | 结构化目录、关键认识、不同观点、未解问题、引用 |
| 案例复盘 | 这次经历究竟让我学到了什么？ | 事前判断、实际过程、执行偏差、竞争解释、后续问题 |
| 方法说明 | 下次遇到类似情况，我准备怎么做？ | 适用范围、条件、步骤、失效、风险与相关案例 |

它们不等于四套强制表单。初次收集只要求原始内容；其余逐步补齐，AI 先提供草稿，用户可以直接修改或继续说。

### 阅读的层次

先看标题与一句话认识，打开后先读正文；需要时再展开案例、不同解释、来源及版本。只在影响当前使用时突出冲突或过期资料，避免每张卡充满状态标签。

知识卡显示“还没想清”“已有自己的理解”“值得再看”等学习进度；来源核验和实践证据仍独立保存。界面显示用户自己的表达与 AI 建议的区别，不能因为点了“看过”就标记“已掌握”。

### 学习怎样真正发生

围绕当前问题，提供四个自然动作：

- **用自己的话说**：先让用户解释一句，AI 只追问最关键的模糊点。
- **比较一下**：把两个观点的前提、分歧与适用情境并排展示；保留无法裁决的部分。
- **找个例子**：优先从真实历史找案例，找不到时明确使用教学示例。
- **下次怎么用**：选择查阅、观察练习或形成候选方法，不默认要求交易。

复习不做机械打卡。打开相关计划时可以提示“你之前对这个问题的认识”，也可由用户选择一个以后回想的时间。对哲学观点或未定论认识采用讨论与对照，不用 AI 单方面判对错。

## 6. 方法需要有自己的完整生命周期

方法对象从候选开始，逐步补充：

- 名称与要解决的问题。
- 适用市场、交易周期和环境；明确不适用情形。
- 观察什么证据，哪些条件仍不明确。
- 何时考虑行动，何时继续等待，何时放弃原判断。
- 执行步骤、风险处理及所需工具。
- 支持案例、反例、未参与的机会与交易成本资料。
- 当前版本、用户态度、试用状态及证据范围。

用户界面可以呈现“构思中 → 观察试用 → 我在采用 → 已暂停”。证据成熟程度另列；“我在采用”表示用户选择使用，不表示统计证明有效。

### 实践先小后大

首次试用可只做观察：锁定当时可见的信息和判断，稍后补充结果。已有历史回放需要先隐去后续结果，避免拿结局改写事前判断。模型不得伪造历史可见性。

所有结果都能进入案例：符合条件但失败、不符合条件却上涨、选择放弃、真实成交。不能只收集成功截图。资料不全时允许保存，明确缺口，不计算伪精确胜率。

一条复盘结论应明确下一次改变什么；也允许结论是“当前资料不足，维持原方法”。复盘不会必然生成新规则。

## 7. 交易体系是一份持续修订的个人交易手册

首页先展示“当前我怎样做交易”和最近的具体变化。道、法、术、器作为组织视角保留，但不能替代手册中必须回答的问题。

| 体系内容 | 核心问题 | 道法术器对应 |
| --- | --- | --- |
| 目标与生活约束 | 为什么交易，可投入什么，哪些边界不能碰？ | 道 |
| 参与范围与机会 | 做什么市场、周期和机会，哪些不做？ | 道、法、术 |
| 判断与执行 | 什么情况下观察、计划、行动、持有、退出？ | 法、术 |
| 风险与资金使用 | 如何决定投入，整体暴露怎么检查？ | 法、器 |
| 复盘与修订 | 何时检查，什么证据值得改变做法？ | 法、术 |
| 工具与资料来源 | 完成上述动作，实际需要什么？ | 器 |

短线与中长线共享个人目标和总体约束，各自有方法和执行规则；不能把短线失败自动解释成长线持有。工具需要结合资料时点检查，缺账户数据不能推导完整账户风险。

### 道

展示用户确认过的目标、原则、取舍及其缘由。它可以从真实困扰逐步形成，无需首次进入就填写长问卷。理念变化用原话记录。

### 法

展示正在生效的纪律、适用范围和具体操作要求。修改时展示“原来怎样 → 建议怎样 → 为什么 → 会影响哪些方法和计划”，由用户明确决定采用、修改或保留原版。已有明确确认不再重复询问。

### 术

首先展示用户自己的方法：正在构思、正在观察试用、实际采用和已暂停。每种方法都能打开定义与证据，并直接创建一次观察或计划。

软件提供的学习、计划检查、复盘、体系回顾等 skill 是背后的工作能力。界面以“帮我比较”“检查这次计划”“复盘这个案例”出现，并携带当前对象，不要求用户挑技术名称。

### 器

是实际可用的计算、行情、台账、条件检查，以及未来确有需要的资料阅读与案例回放工具。提供统一工具柜，但优先出现在任务需要的位置。例如计划中的仓位字段旁打开计算，结果经用户选择填回计划；不会写成已成交。

## 8. 日常入口保持三个，但重新分工

| 入口 | 打开后首先看到 | 最主要的动作 |
| --- | --- | --- |
| 工作台 | 继续上次的问题、当前最值得处理的一件事、自然输入区 | 随手说、继续学、检查计划、回顾经历 |
| 知识库 | 专题与整理成果，可切换全部成果列表 | 查阅、理解、比较、回想 |
| 交易体系 | 当前个人手册、自己的方法、待决定的具体修改 | 使用方法、制定计划、确认或修订 |

对话融入工作台和各对象详情。桌面可在阅读内容旁展开讨论，手机在当前内容下继续；回到内容后保持阅读位置。对话历史仍可找回，但不承担知识目录的功能。

工作台不放资料总数、模型数量或“体系完成百分比”作为主内容。最多推荐一件主要事项和两件次要事项，优先级依据用户当前关注、明确时间和相关性；每条说明出现原因。可以忽略、暂停或关闭提示，不制造未清空焦虑。

默认先围绕一个重点专题持续积累，也允许并行多个专题。新用户从一个正在学习的问题开始，目标与生活约束在相关任务中逐步补齐；老用户先看到已有专题整理建议和真实缺口，不重新填写一遍背景。

模型选择、完整技能目录、来源档案、技术状态收进次级位置。

## 9. 一条完整使用旅程

以下是交互设计示例，不是新的交易规则，也不写入个人记忆。

1. **随手输入**：“看到一段讲超跌反弹的内容，我不清楚底部成立到底凭什么。”
   - 原文和附件保留。
   - 助手检索已有相关内容，给出简短理解与关联建议。
   - 回执：“已收下；可接着整理‘如何判断超跌后的机会’。”点击更正即可调整归属。

2. **接着理解**：打开同一个问题，看到原文、自己的理解和一个关键追问。
   - “你目前能观察到的条件是什么？”
   - 不把“跌得多”“有人说洗盘”自动改写成已确认信号。
   - 产出一张可编辑知识卡，原文在下面。

3. **组织成成果**：新知识进入既有专题。
   - 更新专题草稿中相关段落，显示新增、冲突和缺口。
   - 用户手写内容不被后台覆盖；可以接受建议、编辑或保留两种认识。
   - 仍只想学习时，到这里就足够。

4. **准备一次观察**：点击“看看怎么用”。
   - 从知识卡带入候选方法，逐步写清周期、条件、失效与未知。
   - 可以只记录一次事前观察，不要求投入资金。
   - 锁定本次使用的方法版本和依据。

5. **回来复盘**：继续同一个案例，补充实际发生的情况。
   - 先对照原判断，再讨论执行，最后才看结果。
   - 区分“条件没成立”“执行偏离”“方法可能不适用”“资料仍不足”。
   - 支持和反例都回到方法卡，新的疑问回到专题。

6. **审阅体系变化**：累积到有值得讨论的变化时，显示一份具体提案。
   - 例如把模糊用语改成可观察定义，并保留证据仍有限的说明。
   - 用户可以维持现状、继续试用、暂停方法，或明确采用新版本。
   - 下一次计划自动读取当前生效版本；旧案例保留旧版本。

这条旅程的关键是：**始终在推进同一个问题，不必复制内容、寻找聊天、重复交代背景或手工给每一步分类。**

六步是讲解过程的顺序，不是正式界面的六道必做关卡。真实交易可以从计划或复盘进入，已有方法可以直接实践，单纯查资料也不必启动学习任务。

### 怎样融入日常

以下只是可调整的使用节奏，不生成定时任务：

- **随时有输入**：用几十秒发一段语音或材料，收到简短回执；可以不当场处理。
- **有一小段空闲**：工作台续上当前专题，花几分钟弄清一个问题，留下自己的解释。
- **准备行动**：从方法中创建计划，既有条件、纪律与案例随之出现；只补当前缺少的部分。
- **有了新结果**：补充实际情况，做一次简短对照；值得深挖才展开完整复盘。
- **阶段性回顾**：看本阶段哪些理解改变、哪些方法积累了反例、哪些提案需要决定；同时可以选择保持原体系。

最终应让用户感到“今天只推进了一小步，但上次学过和经历过的东西都还在发挥作用”。

### 智能体应该如何介入

用户不需要切换“归档员、研究员、教练”等模式。智能体根据当前表达与对象采取合适的动作：随手记录时简短收下，学习时追问最关键的理解缺口，研究时先确认问题和实际资料覆盖，计划时找回对应方法和纪律，复盘时先还原当时信息。

不确定是在表达想法、制定计划还是报告成交时，保留原话并只询问必要差别。收集阶段不强制教学，用户请求快速结论时不连续追问；深度练习由用户选择。自动整理负责减少劳动，重要意义和体系取舍仍由用户决定。

对外部文章或文件，要标明实际读取范围与来源；尚未接入的网页抓取或研究能力不能在界面显示为已完成。对同一问题的回答应更新同一份草稿或形成明确的新版本，不每聊一次就制造一张重复成果卡。

## 10. 顺畅来自减少重复劳动

- 多种输入一次保存，原件、转写和派生成果互相关联；失败后保留输入，可继续重试。
- 简单关联、标签建议和摘要草稿可自动完成，并可更正；正式认同、体系规则和重要内容合并显示明确差异。
- 重要信息缺失时只问当前必要的一件，不一次抛出完整表单。
- 点“继续”携带专题、记录及版本、正在解决的问题、上次进度；不能只是跳去空白对话。
- 短回答先给结果；依据、讨论和来源按需展开，不默认生成四层长报告。
- 用户理解、AI 建议、原始来源分别标明；保存后能看到保存对象，避免只有聊天里的“已记住”。
- 学习和实践允许中断，返回后从原位置继续；同一事项只有一个待办，不因多次聊天重复生成。
- 没有明确日程或授权时只在打开工作台时整理提示，不宣称后台盯盘或主动推送。
- 一段时间不用也不显示逾期红点海；回来先选择是否继续原问题。

## 11. 视觉方向

保留温润、安静的阅读气质，缩小大标题和装饰区域，把首屏交给实际内容。桌面采用清晰的目录与阅读面，手机优先一列阅读与固定位置的当前主动作。

专题页像一篇不断完善的文章，方法页像一份可以拿来执行的说明，体系页像自己的手册。卡片主要用于扫读或推荐下一步，不把所有内容装成同样的卡片墙。

层次靠内容关系、留白、字号和对齐建立。每个区域有一个主要动作；操作后的结果在原位置出现。状态变化使用短过渡，支持减少动画设置；不为装饰延迟操作。

## 12. 下一阶段实现范围与顺序

继续复用现有前端、Python、SQLite 和原引擎。此时真正缺的是持续对象和跨步骤流程，技术栈调整不作为这次设计的前置工作。

### 第一阶段：打通一个问题的学习与积累

交付专题、可编辑知识卡、上下文内讨论、持续草稿、来源回查及一个可继续的下一步。工作台、知识库、交易体系开始共享这些对象。

验收：从一段输入出发，形成自己的解释，加入专题；退出再回来无需重新描述背景；原始来源可查；编辑不被后续 AI 输出覆盖；原文、来源事实、个人理解和教学示例不会混淆。

### 第二阶段：从知识走到方法和实践

交付个人方法卡、事前观察或计划、关联案例、执行对照和复盘回流；工具可以从当前任务调用并选用结果。

验收：同一方法至少贯穿一份隔离计划、一个支持案例和一个反例；案例绑定具体版本；计划不被当成交；缺数据不会生成完整风险结论；暂停的方法不再默认推荐。

### 第三阶段：让个人体系可用、可修改

交付个人交易手册、缺口梳理、当前规则版本、修改差异、明确确认和历史回看。复用可信人工确认边界，模型没有自行生效的入口。

验收：一份修改可以采用、修改、暂缓；用户仅需针对最终具体差异确认一次；已存在的明确确认被识别；旧案例不会按新纪律重新判违规；未通过的提案不会进入执行检查。

### 第四阶段：低打扰地帮助坚持

在前三阶段真实使用后，增加可选的学习回想、定期回顾、相似情境提醒和跨案例比较。先验证这些提示确实有用，再考虑定时通知。

完整下一版的完成标准包括前三阶段，不能只做第一阶段页面就宣称完整成长闭环已经实现。每阶段都先使用隔离资料验收，再逐步带入真实使用。

## 13. 与现有数据和引擎如何衔接

新增的领域对象应有清晰职责：专题、知识成果、个人方法、实践案例、继续事项。它们引用既有原话、来源、记录、规则和明确版本，避免把所有内容塞进标签和一大段文本。

- 原记录及更正版本保留；旧收藏、归档只是视图偏好，不能当作用户已认同。
- 导入旧资料时先做只读盘点和整理建议，显示重复、未知与可能相关的专题；用户不必重新输入。
- 相近候选心得可以建议并入一个专题，但合并不丢原话，冲突不被消音。
- 旧分析、复盘按已存在的成果内容展示；“类型是 analysis”不能作为质量或掌握程度证明。
- 原业务库与新的领域表通过明确的迁移与版本管理衔接；阅读偏好库不承载正式规则状态。
- 搜索先用现有内容、专题和真实引用实现上下文找回；是否增加向量检索以漏检案例决定。
- 原 runtime_core 保持不变；协同、提案和产出校验在独立扩展中完成。
- 自动分类只在确有依据时关联，不确定时保留待整理；用户可一键纠正并保留理由。

本稿仅设计产品；未更改个人交易记忆、未激活纪律、未修改生产行为。小程序继续暂停调试。

## 14. 怎么判断产品真的有用

不设置虚构的“交易水平分”“体系完善率”。用真实使用过程回答：

- 收到一份材料后，能否很快找到它属于哪个问题，以及自己的理解？
- 隔一段时间，能否不重读整段聊天就解释并使用这条认识？
- 写计划时，相关方法和自己的边界是否自然出现？
- 复盘能否指出一个具体差异，而非再写一篇套话？
- 同一类错误再次发生时，系统能否提供当时的真实提醒依据？
- 用户能否明确说出最近一次体系修改，以及为何采用或拒绝？

如果后续观察执行改善或重复错误变化，必须同时记录机会数、信息完整性及统计窗口；单独看错误条数或盈亏不能归因给产品。

第一次真实验收应由用户带入一份正在学习的材料，完成一次“理解—专题—方法草稿”，随后用一个真实可回查案例继续。最重要的反馈是：是否减少了重复表达，是否帮助弄清问题，是否知道下一步做什么。
