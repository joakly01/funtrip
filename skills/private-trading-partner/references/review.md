# 复盘、心法与体系

复盘先检索事前 plan、成交 trade、当时 strategy 和原始判断，分别评价逻辑、方法、执行、结果及不确定性。只有事后回忆时明确标注。用 review_save 归档并关联 refs。

心法和学习先记录出处与原意，再关联个人案例。成功/失败模式先用 hypothesis_save 建立候选假设，列出反例、适用环境、失效条件和下一步验证方式。没有完整样本不要编造胜率或收益率。

个人资金时间边界由用户决定；交易方法的有效性另需证据。采用正式规则不代表已证明有效。

## 规则版本

strategy_propose 输入的是拟生效的完整规则集合，先 strategy_get 后比较，避免无意丢掉已有规则。每条含 id、text；可判定规则额外包含 condition，例如 field/operator/value。没有用户确定的阈值不要补数字。

提案产生 base_id 和 digest，当前不生效。重要规则激活没有普通 MCP 工具，使用单独 CLI，且必须满足：

1. 已展示具体差异，用户明确确认的是该提案。
2. 用户确认原文必须严格为 `确认 <提案编号> <完整 digest>`；否定、引文或附条件表达不能激活。不足时保持提案，不伪造用户原话或自行补成确认。
3. 保存真实确认原文，调用 `python3 -m trading_agent approve-rule <proposal_id> <digest> <confirmation_source_id>`。

这是首版的保守确认机制，会比普通记录多一次明确确认；后续可以用真实 UI 确认凭据替换。不可用 shell 直接写数据库绕过它。

## 进化

用 evolution_record 保存发现的问题、证据、修改与回退说明。工具代码或提示词调整前后运行项目测试并增加真实失败案例。固定案例和新案例分开，不能只凭自己觉得更聪明宣布进步。

当前外循环由用户新输入、主动复盘触发，没有后台循环。不要把 follow_up 字段等同已启用的提醒任务。
